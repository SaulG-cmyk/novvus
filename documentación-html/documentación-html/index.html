NOVVUS CORE

Nivel básico

Plataforma modular de software empresarial: un kernel en Rust sobre el que corren módulos de negocio escritos en Python, con un frontend unificado en Next.js y una sola base de datos PostgreSQL compartida por todas las organizaciones. Esta documentación está escrita para que una persona que llega hoy al equipo, sin conocer el proyecto, pueda instalarlo, usarlo y después construir sobre él.

La idea en 60 segundos

Si conoces Odoo o SAP, la idea te sonará: hay un núcleo que resuelve lo que todas las aplicaciones necesitan (usuarios, permisos, organizaciones, instalación de apps) y encima corren aplicaciones de negocio (CRM, Proyectos…) que no repiten ese trabajo. La diferencia es la arquitectura, pensada desde cero con herramientas actuales:

Core de plataforma   >   Sistema de módulos   >   Aplicaciones empresariales
   (kernel, Rust)         (novvus-sdk, Python)      (CRM, Proyectos, Ventas México…)
  • El kernel (Rust, 7 crates) es el único dueño de la autenticación, los permisos, el ciclo de vida de los módulos, las migraciones, el bus de eventos, los archivos adjuntos y la colaboración (chatter y notificaciones).
  • Los módulos (Python) son las aplicaciones de negocio. Se escriben con novvus-sdk de forma declarativa: declaras modelos, permisos, eventos y vistas; el SDK genera la API y habla con el kernel por ti.
  • El frontend (Next.js 16, React 19) es un administrador de aplicaciones: un launcher, una tienda de apps y los ajustes. Cada app abre a pantalla completa. Y gracias a las vistas genéricas, un módulo obtiene lista, formulario, kanban y calendario sin escribir React.
  • Una sola base PostgreSQL 16 aloja a todas las organizaciones (multi-tenant). El aislamiento entre ellas lo garantiza la base de datos con Row-Level Security, no la buena voluntad del programador.
  • Un módulo jamás toca la autenticación ni las tablas de otro módulo. Todo pasa por contratos: la API del kernel, los eventos y las extensiones declaradas.

Arranque rápido

Hay dos formas de tener Novvus Core corriendo. Elige según lo que quieras hacer; los detalles completos están en Instalación.

Probarlo en tu computadora (demo con datos de ejemplo)

Solo necesitas Docker Desktop y Python. Funciona en Windows, macOS y Linux:

git clone https://github.com/artmichel-dev/Novvus-Core && cd Novvus-Core
python install.py        # construye, enciende, siembra la demo y abre el navegador
Credenciales de demo: demo@novvus.dev / demo-password-123 en http://localhost:3000. La organización «Novvus Demo» viene con empresas, contactos, leads y un pipeline con oportunidades, más los roles «Ventas» y «Gerente de ventas».

Instalarlo en un servidor (producción)

En un servidor Linux con Docker, el CLI administrativo novvus lo hace todo sin preguntas y sin necesitar el repositorio:

curl -fsSL https://install.novvus.dev/install.sh | bash   # instala el CLI en /usr/local/bin
sudo novvus install                                        # descarga imágenes, genera secretos y levanta 6 servicios
novvus status                                              # salud de cada servicio + URL
En producción no hay usuario demo. La web queda en http://<servidor>:8077 y arranca en modo first-run: creas tu cuenta, creas tu organización y habilitas las apps desde la tienda. Nunca publiques el puerto 8077 directamente a internet; ponle un proxy HTTPS delante (ver Instalación).

Estado del proyecto

La versión actual es la 0.1.6 (archivo VERSION en la raíz del repositorio, única fuente de la versión de plataforma). El proyecto se construyó en dos series de fases y ya es un producto distribuible.

v11Kernel en Rust (7 crates)completa

v13Módulo CRMcompleta
v14Frontend Next.jscompleta
v15Interoperabilidad y empaquetado (módulo Proyectos, eventos)completa
v21Vistas genéricas y pipeline de metadatoscompleta
v22Adjuntos y servicio de archivoscompleta
v23Extensiones entre módulos (módulo SalesMX)completa

Producto—Distribución: CLI novvus, imágenes GHCR, install.sh, actualización seguracompleta
Producto—Firma criptográfica de releases, novvus backup/restorependiente
Fuente de verdad. Esta documentación es la versión narrada y didáctica. Los contratos formales viven en documents/docs/ dentro del repositorio: 19 documentos (ARCHITECTURE, MODULE_CONTRACT, BUILDING_MODULES, DATA_MODEL, MULTITENANCY, EVENTS, SECURITY, VIEWS, FILES, EXTENSIONS, CUSTOM_FIELDS, CHATTER, I18N, CLI, DEPLOYMENT, DISTRIBUTION, QA, DECISIONS y BACKLOG). Regla de oro del proyecto: contrato primero, código después — todo cambio de comportamiento se edita primero en esos documentos y solo entonces en el código. Si esta guía y un contrato se contradicen, gana el contrato.
