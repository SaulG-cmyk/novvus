Instalación

Nivel básico

Tres caminos claramente separados: (A) una demo en tu laptop con datos de ejemplo, (B) producción en un servidor Linux con el CLI novvus, y (C) el modo desarrollador para modificar el código. Elige uno con la tabla de abajo y sigue solo esa sección; al final hay una lista de verificación común.

Resumen para decidir

CaminoÚsalo cuandoNecesitasComando principalEntras en
A · Demo local Quieres ver la plataforma completa funcionando en tu computadora, con datos de ejemplo. Docker Desktop + Python 3.8+ python install.py http://localhost:3000 con demo@novvus.dev
B · Producción Vas a instalar en un servidor Linux para usuarios reales, con actualizaciones seguras. Servidor Linux x86_64/arm64 con Docker y root sudo novvus install http://<servidor>:8077, creas tu cuenta (first-run)
C · Desarrollador Vas a modificar kernel, SDK, módulos o frontend con recarga rápida. Docker, Rust, Python 3.12+, Node 22 make up + procesos locales http://localhost:3000
D · Manual Producción sin el CLI (casos especiales: automatización propia, auditoría). Lo mismo que B docker compose -f docker-compose.prod.yml up -d --wait http://<servidor>:8077
Qué levanta cualquiera de los caminos. Seis servicios: postgres (PostgreSQL 16), kernel (gateway Rust), bootstrap (aprovisionamiento de una sola pasada: registra e instala los módulos y termina en Exited (0), lo cual es correcto), los módulos crm y projects, y web (Next.js). El módulo salesmx existe en el repositorio pero no forma parte de ningún docker-compose ni del bootstrap; se despliega a mano en el camino C.

A · Demo local en tu laptop (install.py)

Funciona en Windows, macOS y Linux. El único requisito real es Docker; el instalador está escrito en Python estándar (3.8 o superior) sin dependencias externas.

1
Instala Docker Desktop (o Docker Engine con Compose v2 en Linux) y ábrelo. Si no lo tienes, el propio instalador te lo sugiere: en Windows winget install Docker.DockerDesktop, en macOS brew install --cask docker, en Linux curl -fsSL https://get.docker.com | sh. Si Docker está instalado pero no responde, el instalador intenta abrir Docker Desktop y espera hasta unos 4 minutos.
2
Clona el repositorio y ejecuta el instalador. 
git clone https://github.com/artmichel-dev/Novvus-Core && cd Novvus-Core
python install.py            # instala + enciende + siembra demo + abre navegador
En Windows también puedes hacer doble clic en install.bat (busca py -3 y luego python; si no hay Python sugiere winget install Python.Python.3.12). En Linux/macOS, ./install.sh equivale a python3 install.py. Con python install.py --no-browser no abre el navegador (útil en un servidor de pruebas).
3
Espera. El instalador comprueba que los puertos 3000 y 8000 estén libres (solo avisa), construye las imágenes con docker-compose.full.yml (la primera vez tarda 10-20 minutos porque compila Rust y Node desde cero), levanta todo con --wait, espera al /health del kernel y a la web, y abre el navegador.
4
Entra. En http://localhost:3000 con las credenciales de demo. El kernel queda accesible en http://localhost:8000 (por ejemplo http://localhost:8000/health). 
Usuario:    demo@novvus.dev
Contraseña: demo-password-123
La organización «Novvus Demo» ya tiene los módulos CRM y Proyectos habilitados, los roles «Ventas» y «Gerente de ventas», y datos sembrados (empresas, contactos, leads y un pipeline con oportunidades).

Subcomandos del instalador

ComandoQué hace
python install.pyInstala y enciende todo (idempotente: puedes repetirlo).
python install.py startEnciende sin reconstruir imágenes.
python install.py stopApaga conservando los datos.
python install.py statusMuestra los servicios y el healthcheck del kernel.
python install.py logsLogs en vivo de todos los contenedores.
python install.py updategit pull --ff-only + reconstruir + reiniciar. Conserva los volúmenes (datos).
python install.py resetBorra contenedores, imágenes locales y datos. Pide escribir BORRAR.
Si algo no responde. «Docker no está instalado» → instálalo y vuelve a ejecutar. «El puerto 3000/8000 está en uso» → cierra lo que lo ocupe (otro Novvus, un npm run dev). Construcción lenta → es normal la primera vez; la segunda usa caché. Para ver qué falla: python install.py logs.
Ver más: qué hay dentro de docker-compose.full.yml

Proyecto Docker novvus. Postgres sin puerto en el host (usuario/base novvus), kernel en 8000:8000, bootstrap con NOVVUS_DEMO=1 y SEED=1 (crea el usuario demo, la organización, despliega los módulos, crea roles y siembra datos; guarda los tokens de servicio en el volumen novvus_tokens), módulos crm (interno 8110) y projects (interno 8120), web en 3000:3000. Volúmenes: novvus_full_pgdata, novvus_tokens, novvus_minio. Existe un perfil opcional s3 con MinIO en el puerto 9000 para probar el backend de adjuntos S3. Variables que el bootstrap admite para personalizar la demo: NOVVUS_ADMIN_EMAIL, NOVVUS_ADMIN_PASSWORD, NOVVUS_ORG_NAME, NOVVUS_ORG_SLUG, SEED.

B · Producción en un servidor Linux (CLI novvus)

Esta es la ruta soportada para usuarios reales. El servidor no necesita el repositorio, ni Rust, ni Python, ni Node: el CLI trae la plantilla de despliegue embebida y descarga imágenes ya construidas desde ghcr.io/novvus/*.

Requisitos del servidor

RecursoMínimo útilRecomendado
Sistema operativoLinux x86_64 o arm64 (Ubuntu Server 22.04 LTS)Ubuntu Server 24.04 LTS
CPU / RAM2 vCPU / 4 GB4 vCPU / 8 GB
Disco30 GB SSD50+ GB SSD (los respaldos de novvus update se guardan en el servidor)
SoftwareDocker Engine + Compose v2, curl, acceso root (sudo)Igual; jq es opcional
RedIP pública, puerto 22 solo desde tu IPIP fija + dominio + puertos 80/443 para el proxy
1
Prepara el sistema e instala Docker (una vez, como en cualquier VPS Ubuntu): 
ssh ubuntu@IP_DEL_SERVIDOR
sudo apt update && sudo apt upgrade -y
sudo apt install -y ca-certificates curl gnupg

sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
docker compose version      # debe decir v2.x
2
Instala el CLI administrativo. Descarga el binario estático de tu arquitectura, verifica su SHA-256 contra el manifiesto publicado y lo deja en /usr/local/bin/novvus: 
curl -fsSL https://install.novvus.dev/install.sh | bash
novvus version               # Novvus CLI: 0.1.6 / Novvus Core: not installed
Para fijar una versión concreta: curl -fsSL https://install.novvus.dev/install.sh | bash -s -- 0.1.6.
3
Instala Novvus Core. Sin preguntas: valida Linux + Docker + Compose v2 + root, genera todos los secretos con entropía del sistema, escribe /opt/novvus/docker-compose.yml y /opt/novvus/.env (permisos 600), descarga las imágenes ghcr.io/novvus/{core,web,bootstrap,crm,projects} de la versión exacta del CLI, levanta los 6 servicios y espera sus healthchecks reales (hasta 300 s). Al terminar deja /opt/novvus/novvus.json (versión, fecha, arquitectura; sin secretos). 
sudo novvus install
El puerto web es 8077. Si está ocupado el instalador se detiene y te lo dice; nunca elige otro por su cuenta. Para cambiarlo: NOVVUS_WEB_PORT=8088 sudo novvus install. Si detecta una instalación previa en /opt/novvus, se detiene sin tocar nada.
4
Comprueba el estado. 
novvus status                # versión + tabla postgres/kernel/bootstrap/crm/projects/web + URL
cd /opt/novvus && docker compose ps   # (opcional) la misma información vista desde Docker
novvus status devuelve exit code 0 solo si todo está sano; bootstrap aparece como completed. El kernel no tiene puerto en el host: solo es alcanzable a través de la web.
5
First-run en el navegador. Abre http://IP_DEL_SERVIDOR:8077 (temporalmente, solo desde tu IP; ver paso 6). No existe ningún usuario todavía:
  1. Pestaña Crear cuenta: nombre, correo y contraseña. Será la cuenta administradora.
  2. Crear organización: nombre e identificador para URL (minúsculas, números y guiones, por ejemplo mi-empresa). Recibes el rol Owner.
  3. Entra a Aplicaciones (/apps) y pulsa Instalar y luego Habilitar en CRM; después en Proyectos (depende de CRM: la tienda te mostrará el plan de dependencias y un botón «Habilitar todo»).
  4. Vuelve a Inicio: tus apps ya aparecen en el launcher.
6
Publica con dominio y HTTPS (reverse proxy). Solo la web escucha en el host; Postgres y el kernel viven en la red interna de Docker y el navegador llega al kernel por el proxy interno de la propia web. Para TLS, pon Caddy delante del 8077 (o nginx/Traefik, si lo prefieres): 
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy
Edita /etc/caddy/Caddyfile (Caddy obtiene el certificado solo cuando el DNS ya apunta al servidor): 
novvus.tu-dominio.com {
  reverse_proxy 127.0.0.1:8077
}
sudo systemctl reload caddy
Con el proxy funcionando, cierra el 8077 en el firewall: hacia internet solo deben quedar abiertos 80 y 443 (y 22 desde tu IP).
Reglas de oro en producción. Nunca expongas 8077 sin proxy HTTPS. Nunca abras 5432 ni 8000: en la instalación con CLI ni siquiera existen en el host. No edites /opt/novvus/.env a mano salvo que sepas lo que haces: los secretos los genera y preserva el CLI, y novvus update lo migra línea a línea. Los respaldos y la actualización se explican en Actualización y releases y Mantenimiento.

Guías breves por proveedor

Los nombres de los botones cambian, pero el servidor por dentro es el mismo: Ubuntu + SSH + Docker + los pasos 1-6 de arriba. Lo único que varía es cómo abres puertos: en todos los casos 22 solo desde tu IP, 80/443 públicos, y nunca 8077 público sin el proxy (si quieres probar antes del DNS, ábrelo solo desde tu IP y ciérralo después).

VPS genérico (DigitalOcean, Linode, Vultr…)
  1. Crea un droplet/instancia con Ubuntu 24.04 LTS, 2-4 vCPU, 4-8 GB RAM, 50 GB de disco.
  2. Agrega tu llave SSH pública; evita contraseñas para SSH.
  3. Firewall del proveedor: 22 desde tu IP; 80 y 443 públicos.
  4. Apunta un registro A del dominio a la IP y sigue los pasos 1-6.
Oracle Cloud Infrastructure (OCI)
  1. Crea una VCN con subnet pública, internet gateway y route table hacia internet.
  2. Crea una instancia Compute con Ubuntu. Las Ampere A1 (arm64) funcionan: el CLI y las imágenes se publican también para linux-arm64.
  3. Entra normalmente como ubuntu. Reserva IP pública si el ambiente será estable.
  4. En Security List o NSG: 22 desde tu IP; 80/443 públicos.
OCI tiene dos capas de firewall: las reglas de red de la VCN y el firewall del sistema operativo. Si curl localhost:8077 funciona dentro del servidor pero desde tu laptop no, revisa primero Security List/NSG y después sudo ufw status.
Hostinger VPS
  1. Contrata un VPS KVM con Ubuntu 24.04 y agrega tu llave SSH desde hPanel.
  2. Activa los snapshots del proveedor antes de instalar, si el plan lo permite.
  3. Firewall del panel: 22 restringido a tu IP; 80/443 públicos. Apunta el DNS con un registro A.
  4. Si te entregan acceso como root, crea un usuario operativo para el día a día: 
    adduser deploy
usermod -aG sudo deploy
rsync --archive --chown=deploy:deploy ~/.ssh /home/deploy
su - deploy
AWS (EC2)
  1. Instancia EC2 con Ubuntu Server 24.04 LTS; t3.medium (x86_64) o t4g.medium (arm64) como punto de partida; EBS gp3 de 50 GB.
  2. Key pair SSH. Security Group: 22 desde tu IP; 80/443 desde internet.
  3. Elastic IP si debe conservar la IP; registro en Route 53 hacia esa IP.
  4. Conéctate como ubuntu y sigue los pasos 1-6. Para una etapa posterior: respaldos a S3, logs a CloudWatch.
Azure (Virtual Machine)
  1. VM Ubuntu Server 24.04 LTS; tamaño B2s para pruebas o D2s_v5 para un ambiente estable; disco SSD de 50 GB o más.
  2. Autenticación con llave SSH. NSG inbound: 22 desde tu IP; 80/443 públicos.
  3. Public IP estática si usarás dominio. Conéctate con el usuario creado (azureuser por convención) y sigue los pasos 1-6.

C · Modo desarrollador

Para trabajar sobre el código con procesos locales y recarga rápida. Requiere más herramientas en tu equipo: Docker, Rust stable (cargo), Python 3.12+ y Node.js 22. Aquí no hay bootstrap automático: tú registras el módulo con el CLI del SDK y obtienes su token de servicio.

1
Infraestructura. El docker-compose.yml de la raíz levanta solo Postgres 16 (puerto 5432, volumen novvus_pgdata). 
cp .env.example .env         # secretos de desarrollo; ajusta si hace falta
make up                      # docker compose up -d --wait
2
Kernel (puerto 8000; aplica sus migraciones al arrancar): 
cd kernel && cargo run -p novvus-gateway
3
SDK (una vez, en un entorno virtual de Python 3.12+). Esto instala el comando novvus del SDK: 
pip install -e sdk
4
Registra y arranca los módulos. Necesitas un JWT de un usuario con core.modules.manage (crea tu cuenta y organización en la web o con la API; ver La API). novvus deploy hace register → install → enable e imprime el token de servicio una sola vez: 
cd modules/crm
novvus deploy --kernel http://127.0.0.1:8000 --token <JWT>
# Token de servicio del módulo (guárdalo, se muestra UNA sola vez): NOVVUS_SERVICE_TOKEN=nvk_...
NOVVUS_SERVICE_TOKEN=nvk_... novvus run --port 8110

cd ../projects               # igual, en otra terminal
novvus deploy --kernel http://127.0.0.1:8000 --token <JWT>
NOVVUS_SERVICE_TOKEN=nvk_... novvus run --port 8120
Guarda cada token en un archivo .env dentro de la carpeta del módulo (modules/crm/.env) para no teclearlo cada vez. salesmx se despliega igual (elige un puerto libre); solo aporta extensiones al CRM, no tiene pantallas propias.
5
Frontend (puerto 3000): 
cd apps/web && npm install && npm run dev
Después habilita CRM y Proyectos para tu organización desde /apps.

Atajos en Windows

En el equipo se usan dos scripts locales, start.bat y off.bat, que están fuera del control de versiones (no viajan en el repositorio; si no los tienes, sigue el flujo manual de arriba):

  • start.bat: espera a Docker, levanta Postgres, exige el binario kernel\target\debug\novvus-gateway.exe (si falta: cd kernel && cargo build -p novvus-gateway), abre el kernel en una ventana «NOVVUS-KERNEL», y si existe modules\crm\.env lanza el CRM en 8110, Proyectos en 8120 y npm run dev en ventanas propias. Si falta el .env del módulo avisa que primero hay que hacer novvus deploy.
  • off.bat: cierra las ventanas NOVVUS-*, mata lo que escuche en 8000/8110/8120/3000 y detiene los contenedores.

D · Despliegue manual sin el CLI

Ver más: equivalente manual de novvus install con docker-compose.prod.yml

Es exactamente lo que el CLI automatiza. Úsalo solo si tienes una razón concreta (el CLI no soporta tu plataforma, integras con tu propia automatización). Perderás novvus update con respaldo y rollback automáticos.

sudo mkdir -p /opt/novvus && cd /opt/novvus
# copia aquí docker-compose.prod.yml y .env.prod.example desde el repositorio
cp .env.prod.example .env
# llena TODAS las variables: NOVVUS_VERSION, POSTGRES_*, NOVVUS_JWT_ACCESS_SECRET,
# NOVVUS_JWT_REFRESH_SECRET, NOVVUS_INTERNAL_HMAC_SECRET, NOVVUS_MODULE_DB_PASSWORD,
# NOVVUS_BOOTSTRAP_TOKEN, NOVVUS_WEB_PORT=8077, NOVVUS_LOG_LEVEL=info
openssl rand -hex 32         # un valor distinto por cada secreto
docker compose -f docker-compose.prod.yml up -d --wait
docker compose -f docker-compose.prod.yml ps   # todo healthy; bootstrap Exited (0)

Orden de arranque automático: postgres → kernel → bootstrap → crm, projects → web en ${NOVVUS_WEB_PORT:-8077}. El compose se niega a arrancar si falta alguna variable. Respaldo mínimo de la base:

docker compose -f docker-compose.prod.yml exec postgres pg_dump -U "$POSTGRES_USER" "$POSTGRES_DB" > backup.sql

Si más adelante instalas el CLI, novvus status y novvus version reconocen esta instalación leyendo la versión del .env; novvus install se negará a sobrescribirla.

Lista de verificación final

  • A: python install.py status muestra los servicios running/healthy y puedes entrar con el usuario demo.
  • B/D: novvus status (o docker compose -f docker-compose.prod.yml ps) reporta todo sano y bootstrap terminado en 0.
  • B/D: creaste tu cuenta y organización, y CRM y Proyectos aparecen habilitados en /apps.
  • B/D: el dominio resuelve a la IP, el proxy sirve HTTPS y hacia internet solo están abiertos 80 y 443 (22 desde tu IP).
  • B/D: sabes dónde están /opt/novvus/.env y los volúmenes, y tienes un plan de respaldo (Mantenimiento).
  • C: kernel en 8000, módulos en 8110/8120, web en 3000, y guardaste los tokens de servicio en los .env de cada módulo.
  • El equipo sabe cómo ver logs: python install.py logs (A) o docker compose logs -f en /opt/novvus (B/D).
